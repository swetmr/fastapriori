# Reproducibility artifacts — fastapriori (HybridFIM)

Data, saved results, library source, comparator sources, measurement harness and the notebooks that
regenerate every computed table and figure of the paper from the saved results. All paths are
relative to this folder. The public repository carries this folder without `data/` (only
`data/SOURCES.md`); the complete archive (with `data/`) is distributed separately.

```

                     files under data/ only when present)

                     fetch_real_data.sh (rebuild data/real/ from public sources, verified)
```

## 1 · Check and replot from saved results (any OS, ~25 min, no mining)

Python 3.12 with `env/requirements.txt` and fastapriori 0.2.0; start Jupyter in `notebooks/` and run
in order (headless: `jupyter nbconvert --to notebook --execute --inplace NN_name.ipynb`):

| notebook | does | verified result |
|---|---|---|
| 00_setup_and_verify | checksums, package versions, tools | all shipped files match |
| 01_synthetic_data | regenerates the synthetic datasets with D ≤ 100k from their seeds and compares | 8/8 identical (T20, T30.D2M, T25 skipped: hours) |
| 02_run_grid (replay) | shows the attempted May 2026 grid | 4,955 cells: 4,891 ok, 42 OOM, 22 timeout |
| 03_aggregate | rebuilds `results_rigorous_20260523_115442.csv` from the 8 raw CSVs | equal (max rel. diff 3e-12); writes the coverage table |
| 04_cost_stats | dataset statistics (replay; `FA_MODE=recompute` recomputes from data) | recomputed = saved for all 18 datasets |
| 05_tables_and_figures | every computed table and figure, into `results/derived/part_{a,b,c}/` | |
| 21_final_tables_and_figures | every final table, figure and quoted number from the three campaigns, into `results/derived/final/` (~7 min) | |
| 06_regime_and_ml | regime map + XGBoost threshold sweep and leave-one-dataset-out | sweeps and LOGO metrics identical to saved on Windows (see the note on notebook 06) |
| 07_cost_model_correlation | Spearman(P1, classic ÷ HybridFIM) over 17 datasets | 0.946 (classic-8T ÷ 1T); 0.924 with both at 8T |

## 2 · Rerun experiments (Linux)

`bash env/setup_vm.sh` (`--no-apt` without sudo) creates `~/.venvs/fastapriori`, builds fastapriori
0.2.0 from `lib/`, builds Borgelt and LCM from `tools/` and verifies `SHA256SUMS`. Tested on Ubuntu
24.04 (GCE c3-highmem-8 and WSL). Every run records the installed library version and binary SHA-256
in `results/runs/<campaign>/manifest.jsonl`; a campaign refuses to resume on a different build.

* `02_run_grid` with `FA_MODE=smoke` (2 min), then `FA_MODE=run FA_RUN_CAMPAIGN=<id>` for the full
  May 2026 grid (≈100–120 h on 8 vCPUs, resumable); analyse it with `FA_CAMPAIGN=<id>` → 03, 05, 06, 07.
* October 2026 experiments (each resumable; results in `results/runs/$FA_CAMPAIGN/`):
  `10_setup_and_checks` (tests, smoke, LCM template, Borgelt bound check) → `13_memory_boundary`
  (≈2.5 h) → `15_scaling_sweeps` (D, T, d_max; ≈6 h) → `14_fimi_dense` (5 dense datasets,
  supports 0.5 → 1e-3, k = 2, 3; ≈25 min; `SMOKE = True` first) → `19_phase_profiling` (where
  HybridFIM's time goes at k = 3–5; builds `lib/fastapriori-0.2.1` with `--features phaseprof`
  into `_work/`; ≈3 h).
* `20_seeded_grid` (scatter-seeded Eclat at 1 and 8 threads on the whole grid above pairs, and the dense
  datasets at k = 3; ≈7 h; `SPOT = True` first).
* Never run two mining notebooks at once. Under `tmux`, headless as above.
* **Reanalyse the October 2026 results** (any OS, no mining, no `data/`): `FA_MODE=replay` → 13, 14, 15,
  19 (20 with `FA_CAMPAIGN=vm_20261031`). Runs, builds and data generation are skipped; tables and figures go to
  `results/derived/vm_20261029/` and the checksummed campaign folder is not touched.

If `data/` is absent (repository copy): `bash env/fetch_real_data.sh` rebuilds `data/real/`
byte-identically (Instacart is not shipped: download it from [Kaggle](https://www.kaggle.com/datasets/psparks/instacart-market-basket-analysis)); `FA_MODE=generate` → `01_synthetic_data`
writes the synthetic parquets to `data/synthetic_regenerated/` (T25.D5M takes ~10 h; move them to
`data/synthetic/` to mine them); the FIMI datasets are downloaded by `bench/exp_data.py::fetch_fimi`
on first use. Rebuilt parquet files can differ in bytes with the pyarrow version, so notebook 00 can
report them as changed; notebook 01 compares their content.

## The two campaigns

**May 2026** (`results/campaign_2026-05/`): GCE `us-central1-f`, Intel Xeon Platinum 8481C, 8 vCPUs,
62.8 GiB, Ubuntu 24.04, Python 3.12.3, rustc 1.95.0. fastapriori rows were produced by code identical to
`lib/fastapriori-0.1.0.post1.tar.gz` (PyPI 0.1.0.post1: same Rust sources and Cargo.lock; `classic.rs` and
the classic call path unchanged since the tree that ran the classic/baseline rows). The rows carry no
build fingerprint (empty `git_sha`); the identity rests on the archived source, not on a recorded hash.

**October 2026** (`results/runs/vm_20261029/`): GCE c3-highmem-8 (`us-central1-a`), the same CPU model,
memory and software as in May (recorded in `manifest.jsonl`). Reanalyse with `FA_MODE=replay` (section 2).

Every cell has 1 warm-up + 3 measured runs (median max/min spread per experiment 1.005–1.017). Itemset counts agree
across methods in every cell, with one parse error: the `memory_boundary` row Kosarak / `lcm` / k = 2
reports 1,099,891; the correct count is 534,690 (LCM's 64-bit total overflowed and printed negative,
shifting the per-size vector; the timing is unaffected and the harness now parses negative totals).
LCM counts beyond `-u k` on Kosarak and the dense FIMI data, so its times there are not k-bounded.
`chain.log` records how notebooks 13, 14, 15 (T) and 19 were chained. Paths in logs and outputs are
shown as `/home/user/artifacts`, and host names as `gce-c3-highmem-8`, in both campaigns. The shipped fastapriori 0.2.0 differs from the build that ran only in two
source comments; its compiled extension is byte-identical (checked by building both). The shipped
harness is the one that ran, with renamed files and variables and two later fixes (Borgelt's mining
time, LCM's negative totals). Build ids are hashes of the source files, so a rerun records new ids. `executed/19_phase_profiling.ipynb`
and the `phaseprof` record in `manifest.jsonl` name `lib/fastapriori-0.2.0-phaseprof`, the folder of the
build that ran; `lib/fastapriori-0.2.1` holds the same instrumentation behind the Cargo feature, plus
Python-only fixes outside the measured path.

## Notes on the data and the measurements

`P1` in the saved files is the indicator written rho-intersection in the study, and `rho` is rho-delta.

The per-level timings behind the anchor-and-extend lead over the best external at every level from 3 to 9 on T10.D100k, T20.D1M and T25.D5M are in `results/campaign_2026-05/results_rigorous_20260523_115442.csv`; the higher-order cell of notebook 21 computes the ratios.

* **Real data** can be rebuilt from public sources (`env/fetch_real_data.sh`); see `data/SOURCES.md`
  for each source and its terms. Online Retail is UCI **Online Retail II** (sheet 2009–2010).
* **Synthetic data** was generated with `bench/agrawal_generator.py`, `L = 2N` (the `L…` field in the
  names repeats N), `seed = 42 + i` (table in notebook 01). The shipped files are the ones used in the experiments.
* **Comparators.** Borgelt binaries are built from the shipped sources (apriori 6.31, eclat 5.24,
  fpgrowth 6.21); the binaries used in May are in `tools/bin_2026-05/` (GCC 13.3). pyfim and
  efficient-apriori versions of the May runs were not recorded. Borgelt's tools mine during their
  "writing" step; the harness column `borgelt_mine_s` is total − reading (in the October 2026 rows,
  recorded before this was fixed, it is total − reading − writing: add `borgelt_write_s`).
* **Failures are kept.** The aggregated table drops configurations whose warm-up probe failed;
  notebook 03 writes `coverage_<campaign>.csv` with every attempted cell (42 OOM, 22 timeout in May).
  T25.D5M classic at support ≤ 5e-4 timed out (1,500 s, eight threads) at every k. Kosarak, Online
  Retail and BMS-WebView-1 were not run at k ≥ 3 with support 1e-4; at 5e-4 HybridFIM runs out of
  memory there from k = 4–7 while all external miners finish.
* **"OOM"** means the process exceeded the `ulimit -v` *address-space* cap (60 GiB) or was killed /
  aborted on allocation; it is not an RSS measurement. October 2026 rows also record `max_vsize_kb`.
* **Shared drives.** Borgelt/LCM read their input file inside the timed region; keep `FA_WORKDIR` on
  local disk (both harnesses warn and record the work-dir filesystem type).
* **efficient_apriori** rows (k=2, real data only) time the whole subprocess (Python start, load, rule
  generation); they are not comparable to the library-call times of the other Python methods.
* **Online Retail** mean width is 17.77 in the statistics (duplicate (invoice, item) rows dropped) and
  18.24 in the results table (the timing loader keeps them).
* **Notebook 06 and the platform.** With the pinned versions on Windows (Python 3.12.9, default threads)
  the XGBoost sweeps and the leave-one-dataset-out table reproduce the saved values exactly; the shipped
  copy of the notebook and `results/derived/ml_*` come from that run. On Linux (WSL, 4 threads) they differ
  slightly (fast vs classic: MCC by up to 0.043, AUROC by up to 0.002; leave-one-dataset-out macro AUROC
  0.890 vs 0.882 for fast vs PyFIM). Platform and thread count were not separated as causes. On many-core
  Linux set `OMP_THREAD_LIMIT=4 OMP_WAIT_POLICY=PASSIVE`: the notebook took 6 minutes that way, and
  had not finished after 40 minutes with XGBoost's default of all 16 threads under WSL.
* **Not recoverable:** the exact copies of the May run notebooks (the grid is recovered from the raw
  files), which runner version timed the classic rows (single call vs level chain), and the producer of
  `ablation_results.csv` (5 datasets, medians of 3; no per-run data).
